# v1.4 设计（工作文档）

> 状态：已完成。v1.4.0 已发布。字段以 [ADR-0009](adr/0009-feature-catalog.md)、[ADR-0010](adr/0010-host-identity.md) 为准。
>
> 本文写于 v1.4，下面把嵌入和治理都写成「放到 v1.5」的句子是当时的安排。现行顺序：治理闭环已随 v1.5.0 发布，见 [ADR-0011](adr/0011-governance-loop.md)；嵌入预览已随 v1.6.0 发布，见 [v1.6 设计](v1.6-design.md)；一段话接入已随 v1.7.0 发布，见 [接入说明](integrate.md)。提交前审核在 v1.7 之后，不占用这个版本号。

v1.3.0 已发布。v1.4 只立两块基础设施端口：**功能组装（目录 + 依赖 + 有效能力）** 和 **宿主身份（稳定用户 + 短期凭证 + 频道授权）**。狼人杀由协作者并行。

依据：[路线图](../ROADMAP.md) v1.4 门槛、[ADR-0008](adr/0008-embeddable-composable-chat.md)、[集成设计](integration.md)、[演进](evolution.md)。

## 目标与完成门槛

匿名模式（现有进亭）和宿主身份模式同时成立：

1. 默认 `version: 1` 内存部署行为与 v1.3 一致：无账号、全功能开、访客可进。
2. 关掉的能力绕过 UI 仍被服务端拒绝；依赖缺失在启动或值班台保存时失败，不伪装成功。
3. 宿主签发短期凭证，Pavilo 验证后按授权频道执行发现 / 加入 / 历史 / 发送 / 玩法动作。
4. 伪造、过期、错受众、续期失败、退出后再用旧凭证、频道越权、历史越权有测试。
5. 临时恢复 token 不能升级成宿主身份；operator token 不能当用户凭证。
6. Play：私密视图仍按演员隔离；有稳定用户时断线恢复绑到用户而不是仅绑席位；Agent 席不走宿主 JWT。

用一个最小「已有登录的普通产品」示例驱动接口，不改 Pavilo 内核即可签发凭证并加入预建频道。示例走 WebSocket `join`，不走 iframe。

## 现状（设计必须接上的点）

- 身份只有 **session**：`resumeToken` / `clientSessionId`，公开 `session.id`，昵称频道内唯一。
- `stateStart.capabilities` 是协议能力列表（ack、historyPage、play…），不是功能开关。
- 频道功能全部常开；`readOnly` 是唯一服务端功能限制。
- Config：v1 禁止 `storage/operator/plays`；v2 为 sqlite 家族。未知根键拒绝。
- `/room-info` 对任何能打到端口的人列出全部频道。
- Play 私密快照按 `session.id` 过滤；Agent 席 `kind === 'agent'`。
- 幂等键：`channelId + session.token + clientMessageId`。
- 值班台人员页管席位禁言/请离/IP，不是稳定用户。

## 架构

```text
独立聊天页 / 宿主示例页
        │
   join + 可选 identityToken     （Protocol v4 可选字段）
        ▼
  Identity  验证凭证 → 稳定用户 | 访客
        ▼
  Authorization  频道发现/加入/历史/发送/玩法
        ▼
  Capabilities  实例 ∩ 频道 ∩ 依赖（存储/网关/玩法）
        ▼
  现有 core 命令（message / reaction / historyPage / playAction）
```

Identity 回答「是谁」，Authorization 回答「可以访问哪些预建频道」，Capabilities 回答「这些操作开没开」。三者都在服务端每次命令上检查，不能只在首次 join 检查。

不把 SQL、JWT 库或厂商 SDK 放进 `src/core`。建议新目录：

- `src/identity/`：验签、时钟、issuer
- `src/capabilities/` 或 `src/core/capabilities.js`：有效能力计算（纯函数，可单测）
- `src/core`：join/command 调用上面两个端口

## 1. 功能目录

### 分层

| 层 | 管什么 | 真源 |
| --- | --- | --- |
| 实例 | 存储、身份是否启用、网关是否可用、已安装 `plays` | YAML；网关渠道仍只在 `/admin` |
| 频道 | 图片、回复、回应、提及、输入提示、历史访问、`access`、玩法绑定 | YAML `channels[]`；值班台一旦认领频道目录，覆盖层一并带这些字段 |
| 用户 | 宿主授权频道列表（身份开启时） | 凭证 claims，不写 YAML |
| UI | 按有效能力隐藏按钮 | 不能扩大权限 |

v1.4 **不**做审核开关（没有审核实现）。频道可留 `moderation: off`  implicit，不要先加审核字段。

### 频道功能键与默认

省略等于 **true**，保证旧配置语义不变：

```yaml
channels:
  - id: general
    access: open          # open | authenticated；省略 = open
    features:
      images: true
      replies: true
      reactions: true
      mentions: true
      typing: true
      history: true       # false 时拒绝 historyPage，join 快照也不带历史
```

`readOnly: true` 继续禁止发言；与 `features` 独立。只读频道仍可按 features 关回应、关历史。

实例不需要再写一份「总开关」：关网关 = 不配 token/渠道；关玩法 = 不写 `plays`。身份见下一节。

### 依赖校验（启动 / 值班台保存）

- `channels[].play` 必须在 `plays` 且 `storage.driver: sqlite`（已有）
- `access: authenticated` 要求已配置可用的 `identity.issuers`，否则启动失败
- `identity.guests: false` 必须配置可用 issuer；默认频道可以为 `authenticated`
- 不因为关了 `images` 就要求关掉别的模块

运行期：网关 hang 不把聊天打成失败（已有）；身份验签失败只拒绝该次认证，不拖垮进程。

### 有效能力怎么交给客户端

不把功能开关混进现有 `capabilities` 字符串数组（那是协议协商）。`stateStart` 增加可选对象，旧客户端忽略未知字段：

```json
{
  "type": "stateStart",
  "capabilities": ["ack", "historyChunks", "roomEpoch", "reconnect", "reactions", "typingLease", "mentions", "channelOccupancy", "historyPage"],
  "features": {
    "images": true,
    "replies": true,
    "reactions": true,
    "mentions": true,
    "typing": true,
    "history": true
  }
}
```

协议 `capabilities` 仍表示「服务端是否实现该协议」：例如关了频道 `features.history` 时 **不要** 宣称 `historyPage`，客户端就不会去拉分页。关 `reactions` 时从数组去掉 `reactions`，命令也拒绝。

`/room-info`：只给登录页必要信息；`access: authenticated` 的频道对未认证请求不可见。不返回密钥、issuer secret、稳定用户目录。

### 服务端执行（绕过 UI 也要拦）

| 关闭 | 拒绝 |
| --- | --- |
| `images` | `kind: image` → 明确错误码（如 `FEATURE_DISABLED`） |
| `replies` | 带 `replyTo` 的 message |
| `reactions` | `reaction` 命令 |
| `mentions` | 带 `mentions` 的 message（纯文本仍可含 `@` 字符，但不做提及权威化） |
| `typing` | `typing` 继续可静默丢弃（与只读频道一致）或显式错误；选静默以保持现有只读行为 |
| `history` | `historyPage`；`stateStart` 历史为空块 |

错误码新增 `FEATURE_DISABLED` / `CHANNEL_FORBIDDEN` / `IDENTITY_*`，不升协议号。

## 2. 宿主身份

### 四个身份层

| 层 | 现有 | v1.4 |
| --- | --- | --- |
| 稳定用户 | 无 | 宿主 `sub`（`userKey`），仅服务端与值班台可见，不进公开 roster/消息 |
| 会话 | `resumeToken` | 不变；恢复仍靠它 |
| 连接 | WebSocket peer | 不变 |
| Agent 席 | `kind: agent` | 不接受用户 JWT；不能用 JWT 冒充 Agent |

昵称仍是显示名。访客没有 `userKey`。历史匿名消息 **不** 按同昵称绑定到后来的宿主用户。

幂等键 **继续** 用 session token，不改成 userKey。可靠性跟连接走，归属跟用户走。

### 凭证

宿主后端签发，Pavilo 只验证。不自建账号。

推荐 v1.4 只实现 **一个 issuer + 配置钉死的算法**（不信任 token 头里的 `alg`，对齐 RFC 8725）：

- 算法：`HS256`，密钥来自 YAML 或 `PAVILO_IDENTITY_SECRET`（覆盖文件）
- 为何先 HMAC：一个实例服务一个应用，和 `operator.token` 运维模型一致，示例后端好写
- 密钥在 Pavilo 进程里意味着 **Pavilo 也能签发**；禁止浏览器、`/room-info`、日志出现密钥。文档写明：生产更宜后续加 Ed25519（私钥只在宿主）
- 时钟：验证 `exp` 必填，允许小 `clockSkewSec`（默认 60）；拒绝 `alg: none`、未知 iss/aud

建议 claims（实现 ADR 锁定名称）：

- `iss`：配置的 issuer id
- `aud`：配置的 audience（建议实例自己填的字符串，如 `pavilo`）
- `exp` / `iat`
- `sub`：稳定用户主键（1–128 字符，`[A-Za-z0-9._:-]+`）
- `name`：可选显示名，经现有 `cleanUsername`；缺省则用 sub 截断
- `channels`：字符串数组，授权的预建频道 id；空数组 = 无频道

TTL：建议上限 15 分钟。续期 = 宿主再签一张，客户端再 `join` 或后续可加 `refreshIdentity`；v1.4 **可以先只支持重新 join**，不先造复杂刷新命令。过期后已建立的 session：下一条需授权的命令拒绝并断开（明确 close reason），不降级成有权限访客。

### 配置（v1、v2 都允许 `identity`）

不新增 Schema 版本。`identity` 加入 v1 与 v2 根键（身份不强制 sqlite）。未写 `identity` = 纯访客，与现在相同。

```yaml
identity:
  guests: true                 # false 时必须带合法凭证才能 join
  audience: pavilo
  clockSkewSec: 60
  issuers:
    - id: app
      alg: HS256
      secret: ""               # 或环境变量覆盖
```

`guests: false` 在 memory 下合法。Play 仍要 sqlite。

值班台：**不**在 v1.4 做身份密钥 UI（避免和 operator token 派生逻辑缠在一起）。YAML / env 为真源。人员页可只读显示席位是否有 `userKey`，禁言/请离仍针对这一席。

### 进入协议（无 SDK）

Protocol v4 可选字段，旧客户端不发即访客：

```json
{
  "type": "join",
  "protocolVersion": 4,
  "username": "北岸的猫",
  "clientSessionId": "…",
  "channelId": "general",
  "identityToken": "<jwt>"
}
```

- 无 token + `guests: true` + 频道 `access: open` → 现有访客
- 无 token + `guests: false` → `IDENTITY_REQUIRED`
- 坏 token → `IDENTITY_INVALID` / `IDENTITY_EXPIRED`，**不**回落访客
- 合法 token 但 `channels` 不含目标频道或频道 `access: authenticated` 未授权 → `CHANNEL_FORBIDDEN`
- 恢复：resumeToken 命中的 session 若带 `userKey`，新 join 的 token `sub` 必须相同，否则 `SESSION_CONFLICT`
- 切频道：检查当前身份对目标频道的授权，以及目标频道 features/access

身份 **不** 放进 URL、不放进 `/room-info`。示例页由宿主自己的源提供，用 JS 把 JWT 放进 `join`（宿主页连 Pavilo WS 时配 `allowedOrigins`）。

独立 Pavilo `/` 登录页 v1.4 **保持用户名进亭**。`guests: false` 时登录页提示「需要宿主应用接入」，不在独立页做宿主账号表单。

### `/room-info` 与发现

| 请求 | 可见频道 |
| --- | --- |
| 未认证 | `enabled` 且 `access: open` |
| 已在 WS 里 join 成功 | `stateStart` / 切频道列表 = 授权 ∩ 启用 |

不要为 v1.4 新增带 Authorization 的 HTTP 频道目录。嵌入 SDK 的发现 API 留给 v1.5。

## 3. 对 Play 与人员治理的影响

- 公开 `playAction` / `message` 走同一套权限、限额、features。
- 私密 `playState`：仍只给授权演员。切频道或换成另一个 `sub` 不得沿用旧私密快照。
- 演员键：有 `userKey` 时用 `userKey`，否则 `session.id`。这样宿主用户刷新拿到新 session、同一 JWT `sub`，可以对回同一角色。访客仍用席位。
- Agent 继续占座位、不占 WS；不验用户 JWT。
- echo 夹具加 1–2 个测试即可验证「同 sub 恢复 / 换 sub 看不到私密」；不改 echo 玩法规则。
- 人员页：列出席位的 `userKey`（若有），禁言/请离/IP 语义不变。稳定用户封禁是 v1.5。

## 4. 驱动示例

`examples/host-identity/`（或 `docs/examples/...`，实现时定目录）：

1. 小 Node 服务：硬编码两个用户登录，签发 HS256 JWT（`sub` + `channels`）。
2. 一页宿主 HTML：登录后对 Pavilo `ws://.../ws` 发带 `identityToken` 的 `join`。
3. README：Pavilo 用 sqlite 或 memory + `identity` YAML、`allowedOrigins` 含该示例源。
4. 不修改 `src/` 即可跑通。

这不是 npm SDK，也不是 iframe。它证明身份端口，给 v1.5 嵌入留同一 JWT。

## 5. 兼容与迁移

- 旧 YAML、旧客户端、旧 resume 流程必须继续可用。
- 未知 `identity` / `features` 键仍走严格 schema：只允许 ADR 列出的字段。
- 数据库：v1.4 **尽量不**为身份建用户表。稳定用户只在进程内 session 上。持久封禁/审计是 v1.5 + sqlite。
- 若 Play 演员键改成 userKey，对局中升级会拆开「仅有 session.id 的旧对局」。可接受：文档写明身份开启后新开的一局才保证按用户恢复；或 echo/测试只用新对局。
- 不把规划中的嵌入字段写进 `pavilo.example.yaml`。身份和玩法只出现在 `pavilo.sqlite.example.yaml` 的可选注释块。

## 7. 测试清单（发布门槛）

- 默认配置：无 `identity`、无 `features`，v1.3 行为不变
- 关 `images` / `reactions` / `history`：协议命令失败；开着的功能不受影响
- `access: authenticated` 但未配 issuer：启动失败
- 访客进 open 频道；进 authenticated 失败
- 合法 JWT 进授权频道；未列频道失败
- 伪造签名、过期、错 `aud`/`iss`、operator token 当 JWT
- `guests: false` 无 token → `IDENTITY_REQUIRED`；坏 token 不回落访客
- resume：同 `sub` 成功；不同 `sub` 用同一 resumeToken → `SESSION_CONFLICT`
- 凭证过期后发消息被拒，不保持授权访客
- `/room-info` 不列出 authenticated 频道、不含 secret
- Play：同 `sub` 恢复看到私密；换 `sub` 看不到；Agent 不需 JWT — 已做（echo + JWT，新 session 仍用 `userKey`）
- 示例：干净环境按 README 走通登录→join→发言 — 已做（2026-09-21：ada 进 staff 并 ACK；guest 进 staff 为 `CHANNEL_FORBIDDEN`；`/room-info` 不含 staff；浏览器 Origin 为示例端口）

浏览器：独立页关图片时附件入口消失。宿主示例至少 Node 集成测试；有余力再加一页 Playwright。

## 风险

- **HMAC 密钥与 operator token 混淆**：分环境变量、分文件字段，禁止共用。
- **`/room-info` 过滤改变现有「列出全部频道」**：只在出现 `access: authenticated` 时改变；全 `open` 时与现在一致。
- **独立页没有宿主登录**：是故意的；v1.4 证明端口，v1.5 把同一 JWT 送进 iframe。
- **关 `mentions` 的语义**：拦权威 `mentions` 字段，不扫描正文 `@`，避免误伤。
