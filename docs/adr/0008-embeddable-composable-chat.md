# ADR-0008: 独立与嵌入共用的可组装聊天能力

## Status

已接受（2026-09-21）；产品方向已确认。组装与身份已随 v1.4.0 落地。治理闭环已随 v1.5.0 发布，见 [ADR-0011](0011-governance-loop.md)。嵌入预览已随 v1.6.0 发布，见 [v1.6 设计](../v1.6-design.md)。

2026-09-23 修订：不交付浏览器 SDK、npm 包或框架包装。接入以 [接入说明](../integrate.md) 为准。阶段与验收以 [路线图](../../ROADMAP.md) 为准。

本 ADR 替代旧路线中“审核 → 狼人杀 → 访问控制”的串行优先级，以及“只有出现不兼容需求才考虑 v2”的产品边界。v1.x 兼容承诺仍有效；v2 允许必要架构调整，不人为制造破坏。

ADR-0003 的可信脚本加载模型继续有效；其旧版本安排、通用 Extension 示例 API、直接调用厂商 SDK 的 Agent 示例不再作为当前实现指导。ADR-0006 的频道绑定、独立玩法页和已落地 Play 契约继续有效；新增嵌入形态不意味着在聊天气泡中实现玩法，具体扩展仍需契约测试。

## Context

Pavilo 已发布默认临时聊天、可选 SQLite，以及 v1.3 的网关、管理后台、Play/Agent 宿主。项目希望服务更多个人开发者和小型社区，让他们复用自己的登录体系，按需接入聊天与玩法。

现有独立页面、临时席位身份和固定入口尚不能构成稳定嵌入产品。只开放 iframe 响应头会漏掉宿主身份、服务端权限、SDK 生命周期、玩法跳转、隐私和能力开关。另一方面，为接入需求建设多租户平台、原生 SDK 或插件市场会过早扩大维护范围。

## Decision

1. Pavilo 同时提供独立聊天室与可嵌入聊天能力，共用内核与版本主线；默认不持久化、无账号、无 AI 依赖。
2. 首批服务个人开发者与小型社区。独立服务优先，一个实例优先服务一个应用；v2 只接入配置或后台预建的频道。
3. 不交付 SDK 或框架组件。对方用现有登录签发短期凭证，并用 iframe 或系统网页容器打开 `/embed`。定制限于 Pavilo 自己的页面。浏览器脚本包、npm SDK、类型声明和 React/Vue 包装不再作为交付物。
4. 复用宿主身份，保留可选访客，不自建账号系统。用户、会话、连接和 Agent 席位分离；身份、授权与后台登录分离。
5. 实例管理模块和存储，频道配置能力和访问策略；服务端计算并执行有效能力，配置时校验依赖。身份验证不强制 SQLite；当前 Play 的 SQLite 依赖保留。
6. 官方交付基础治理闭环，分别提供身份、授权、审核、事件和 Play 扩展面。异步审核后复查状态，持久化提交后 ACK；事件订阅失败不回滚消息。举报、移除和稳定用户拒绝先于提交前审核，见 [ADR-0011](0011-governance-loop.md)。
7. 扩展由部署者安装并信任，有声明、生命周期、配置校验和兼容测试；不建设沙箱或插件市场，不承诺任意可信脚本故障的进程隔离。
8. 官方狼人杀由协作者与基础设施并行开发，不占用嵌入那一版。v2.0 前必须交付完整参考实现。社区基于同一契约开发更多 Play。
9. v2.0 是稳定集成里程碑，允许必要架构迁移。v1.x 保持兼容，已稳定的契约不能因标注“预览”被重置；每项破坏性变更单列迁移说明。

具体接口边界和失败模式见 [集成设计](../integration.md)，该文档同样不构成已发布 API。v1.4 字段以 [ADR-0009](0009-feature-catalog.md) 与 [ADR-0010](0010-host-identity.md) 为准。

## Alternatives

- **只维护独立 LAN 工具**：继续保留这一模式，但不足以覆盖已有产品的聊天接入需求。
- **仅开放 iframe**：缺少身份、能力组装、宿主控制和生命周期，不能作为完整接入能力交付。
- **同时交付无界面 SDK、组件库和 Node 后端包**：扩大首期公共接口与兼容负担，v2 优先现成页面和独立服务。
- **先完成所有玩法再建设身份与接入**：玩法状态会进一步绑定临时席位和独立页面，增加后续迁移成本；改为并行验证。
- **多租户平台、沙箱与插件市场**：不是首批用户接入所必需，暂缓。

## Consequences

- 用户能从独立临时聊天室逐步选择持久化、宿主身份、治理与玩法，不需要切换产品。
- 维护者新增 SDK、跨来源浏览器、认证、权限及扩展兼容责任；这些能力必须有可复现接入示例和阻塞发布的检查。
- 当前独立页副作用、连接路径、身份归属与配置边界需要逐步整理；v2 可集中完成必要迁移，但默认临时体验和数据一致性不能退化。
- 现有文档必须区分已发布、主分支已实现和计划中。历史 ADR 保留并注明替代关系，当前教程不能展示尚未支持的配置或接口。
- 本次只更新产品与规划文档，不更改运行代码、配置示例、包版本或发布状态。
