# v1.6 设计（工作文档）

> 状态：已随 v1.6.0 发布。本文是这一版的实现说明。消息桥以本文和 [examples/host-embed/](../examples/host-embed/) 为准。要改已发布行为，先写迁移说明再改代码。
>
> 2026-09-23 追加，不改变 iframe 行为：`embed.direct: true` 可以在不写 `ancestors` 时顶层打开 `/embed`，响应仍拒绝被嵌。App 的 WebView 把 JWT 放在 `#pavilo=`，页面立刻从地址栏删除。`?pavilo=` 无效。小程序不在当前接入范围。契约见 [接入说明](../integrate.md)。不发布 SDK。
>
> 本阶段只做**嵌入预览**：宿主页面用 iframe 嵌进 Pavilo 自己的一页，走通跨来源登录和讨论。不是 npm 依赖，不是原生 SDK，也不是小程序插件。

依据：[路线图](../ROADMAP.md) v1.6 门槛、[ADR-0008](adr/0008-embeddable-composable-chat.md)、[集成设计](integration.md)、[宿主身份](adr/0010-host-identity.md)。玩法页契约仍以 [play.md](play.md) 为准。

## 目标与完成门槛

默认部署保持 v1.5：不写新配置时没有嵌入入口，`/`、玩法页和 `/admin` 继续拒绝被嵌。配好宿主来源之后，下面几条同时成立：

1. 宿主与 Pavilo 不同源。宿主后端沿用 v1.4 签发短期 JWT，页面只创建 iframe，不自己打开 WebSocket。
2. 身份通过 `postMessage` 送进 iframe。不出现在 iframe 的 URL、Referer 或 `/room-info` 里。
3. 聊天和玩法切换只发生在这一个 iframe 里。宿主文档的地址不变，也不被玩法页带到 `/`。
4. 拆掉 iframe 或宿主换人之后，服务端连接数回到拆掉之前。旧凭证不能在新 iframe 里接着用。
5. 第三方存储不可用时仍能进亭：嵌入路径不读、不写 `pavilo.resume`。断线重连用这一页内存里的凭证；整页换到玩法再换回来时，由宿主再送一次。
6. 浏览器验收改为阻塞发布。Node 24/26 仍允许失败，那是 v2.0 的门槛。

验收示例是一个已有登录页的小服务，嵌进预建频道并来回发言。玩法切换用仓库里的 `echo`，不要求狼人杀。

## 现状（实现必须接上的点）

这些是 v1.5.0 的代码事实，不是目标。

**整站拒绝被嵌。** `src/transport/http.js` 对 `/`、`/chat.css`、`/client/*`、`/vendor/*`、`/plays/...`、`/room-info` 和 `/healthz` 都加 `X-Frame-Options: DENY`。页面和玩法页还有一份不含 `frame-ancestors` 的 CSP。`src/operator/http.js` 对 `/admin` 同样是 `DENY`。`test/security-headers.test.js` 锁住了 `/`、JSON 和 vendor 的 `DENY`。只删掉聊天页上的这一头，玩法页、静态资源和后台会不一致，也不能表达「只允许这几个宿主」。

**玩法会卸掉当前文档。** `client/app.js` 的 `redirectIfPlayChannel` / `switchChannel` 用 `location.assign('/plays/<id>/?channel=')`。`client/play.js` 从玩法回到普通频道时 `location.assign('/')`，没有会话时 `location.replace('/')`，并用 `sessionStorage` 的 `pavilo.next` 让登录页再跳回玩法。`plays/echo/page/app.js` 的离开按钮也是 `location.assign('/')`。这些跳转在独立标签里是对的。放进 iframe 之后，回到 `/` 会撞上仍然是 `DENY` 的响应，iframe 变空白；宿主若把 Pavilo 当成整页应用打开，则会直接离开宿主。

**身份示例不是嵌入。** `examples/host-identity/` 在宿主页面里 `new WebSocket`，把 JWT 放进 `join.identityToken`。因此示例源必须写进 `server.allowedOrigins`。WebSocket 的 Origin 检查在 `src/transport/websocket.js` 的 `validOrigin`：允许名单，或与请求 `Host` 相同的 http(s) 源。嵌入页自己连 `/ws` 时，Origin 是 Pavilo，不是宿主，所以嵌入来源不能拿这张名单来顶。

**会话恢复绑在 `sessionStorage`。** `client/connection.js` 用 `pavilo.resume` 和 `pavilo.channel`。独立页刷新靠它。跨站 iframe 里，Safari 等浏览器可能挡住第三方存储；分区存储即使可用，也和顶层打开 Pavilo 不是同一份。嵌入路径若继续依赖它，换宿主用户时还会串会话。

**独立页拥有浏览器标签。** `client/notifications.js` 的 `updateUnreadUI` 改 `document.title`，并把未读画进 favicon。授予权限后会弹系统通知。复制入口会 `navigator.share` 或把局域网地址写进剪贴板。嵌入页在 iframe 里改自己的 `document.title` 不会改宿主标题，但系统通知和分享不属于宿主。集成设计要求标题、通知和滚动归宿主。

**连接没有给嵌入用的销毁入口。** `createConnection` 会在非故意关闭后重连。文档卸载时浏览器会关掉 socket，但 `pagehide` 现在只停输入状态（`client/app.js`）。往返缓存把页面恢复出来时，若不重新要凭证，可能拿着内存里已经换过的人继续重连。

**配置根键是封闭的。** `config.js` 里 `ROOT_KEYS_V1` 已含 `identity` 和 `moderation`，不含嵌入。未知根键会拒绝启动。身份不强制 SQLite；玩法仍然要 SQLite。

**镜像。** `Dockerfile` 会复制 `admin/`、`client/` 和 `index.html`，不复制 `plays/`。源码可以切到 echo；官方镜像里玩法页今天是 404。

## 架构

```text
宿主页面（另一来源）
  │  只创建 iframe，src = Pavilo 的 /embed
  │  postMessage：hello ←→ identity / 未读 / 过期
  ▼
iframe 里的 Pavilo 文档（/embed 或其后的玩法页）
  │  不读 sessionStorage，凭证只留在这一页内存
  │  自己的 WebSocket，Origin 是 Pavilo
  ▼
现有 join.identityToken、频道授权、玩法命令
```

独立的 `/` 不动。嵌入是另一条启动路径，共用 `client/connection.js`、`client/state.js` 和协议解析，不复制第二套聊天。

宿主模式用路径判断，不用查询参数把 `/` 变成可嵌页面：

| 文档 | 谁打开 | 行为 |
| --- | --- | --- |
| `/`、`/chat`、`/index.html` | 独立标签 | 与 v1.5 相同，含用户名登录和整页玩法跳转 |
| `/embed` | 只应由宿主 iframe 打开 | 隐藏登录，向父窗口要凭证 |
| `/plays/<id>/?channel=&embed=1` | 只作为上面那个 iframe 的内部跳转 | 玩法页；离开时回到 `/embed`，不回到 `/` |

`embed=1` 只改变这一份玩法文档怎么要凭证、往哪返回。它不能用来放宽 `/` 的响应头。

## 1. 响应头：只放开嵌入入口

未配置嵌入来源时，行为与现在完全一样，并且 `GET /embed` 返回 404。

配置了来源之后：

| 响应 | `X-Frame-Options` | CSP `frame-ancestors` |
| --- | --- | --- |
| `GET /embed`（同一份 `index.html`） | 不发送 | 配置里的源，空格分隔 |
| 已启用玩法的 `/plays/<id>/` 页面与 `assets/` | 不发送 | 同上 |
| `/`、`/chat`、`/index.html`、`/chat.css`、`/client/*`、`/vendor/*` | `DENY` | 维持现在的 CSP，不加 `frame-ancestors` |
| `/room-info`、`/healthz` 及其他 JSON | `DENY` | 不加 |
| `/admin` 及其静态文件 | `DENY` | 不加，也不看嵌入名单 |

不使用已经废弃的 `X-Frame-Options: ALLOW-FROM`。只删 `DENY` 而不写 `frame-ancestors`，等于允许任何网站嵌进这一页，本阶段禁止这样做。

`frame-ancestors` 检查的是整条祖先链。因此本阶段不要在嵌入页里再套一层指向 `/plays/` 的 iframe：玩法响应一旦只写 `'self'`，顶层是宿主时浏览器仍会拦住；若把宿主写进玩法页，宿主就能绕过 `/embed` 直接嵌玩法页。内部用同一 iframe 跳转，祖先只有宿主，名单好写，也避免聊天和玩法各开一条连接。

其余 CSP 指令保持现状（`'self'`、现有的 `img-src` / `script-src` / `connect-src`）。嵌入页仍然只加载 Pavilo 自己的脚本。

`/embed` 与 `/` 可以读同一份 `index.html`，但必须按路径分别写响应头。不要根据 `?embed=1` 决定 `/` 能不能被嵌。

## 2. 配置

v1 和 v2 都允许新根键 `embed`。省略或来源为空，等于没有嵌入。不因此要求 SQLite，也不因此要求 `identity`。

```yaml
embed:
  ancestors:
    - http://127.0.0.1:4174
    - http://localhost:4174
```

- 每项是完整源：小写的 `http` 或 `https`、主机、非默认端口。不写路径、查询、用户信息或通配。
- 拒绝 `*`、`null`、`file:` 和空字符串。重复项拒绝。上限 16。
- 不从 `server.allowedOrigins` 抄。那张名单管的是谁可以把自己的页面当成 WebSocket 客户端；嵌入名单管的是谁可以把 Pavilo 的页面放进 iframe。
- 嵌入页自己的 WebSocket 仍走现有 `validOrigin`。同源 iframe 不必把宿主加进 `allowedOrigins`。
- 密钥、operator token 不进这张名单，也不进任何给浏览器的嵌入配置。

`/room-info` 可以增加 `{ embed: { enabled: true } }`，不含来源列表。来源已经写在 CSP 里，浏览器看得到；不必再从 JSON 发一份给无关的客户端。未启用时省略该字段，避免旧客户端依赖它。

值班台不编辑这一段。改 YAML 后重启生效。

## 3. 宿主模式页面

`/embed` 走 `client/app.js` 的另一条启动，不新写一套消息列表。

启动时：

- 不读 `pavilo.resume` / `pavilo.channel` / `pavilo.next`，也不写它们。
- 不渲染用户名登录，不调用 `submitLogin`。先显示一句「等待宿主」，没有表单。
- 向 `window.parent` 发送 `hello`。父窗口就是自己时（有人用顶层标签打开了 `/embed`），停在等待态，不假装是独立聊天室，也不自动改去 `/`。
- 收到合法 `identity` 之后再 `connect`。`getIdentity` 返回内存中的用户名、频道和 `identityToken`。重连时重新读这份内存，以便宿主已经换过凭证。
- 隐藏「复制链接」和系统通知入口。未读仍更新 iframe 内部的「回到底部」，但 `updateUnreadUI` 在宿主模式下不改 `document.title`、不换 favicon、不调用 `Notification`。未读数改由消息桥告诉宿主。
- 「离开」通知宿主并故意关闭连接，不落到独立登录页。

`guests: false` 或频道 `access: authenticated` 时，没有凭证就保持等待，不降级成访客。这条与 v1.4 的 join 规则相同。

## 4. 消息桥

消息桥不是 WebSocket 协议，不升 Protocol v4。字段在发布前都算草案。

子页面发给父窗口：

| type | 何时 | 载荷 |
| --- | --- | --- |
| `hello` | 每个文档一开始，包括从聊天跳到玩法 | `instance`。不含凭证、用户名、恢复令牌 |
| `ready` | `stateStart` 之后 | `instance`、`channelId` |
| `unread` | 未读变化 | `instance`、`count` |
| `connection` | 连接状态变化 | `instance`、`status`：`connecting` / `online` / `reconnecting` / `offline` |
| `identity-expired` | 服务端以 `4010 / identity_expired` 关闭 | `instance`。页面停止重连，不改成访客 |
| `error` | 拒绝进入 | `instance`、`code`（沿用现有错误码，如 `CHANNEL_FORBIDDEN`） |
| `left` | 用户在嵌入页确认离开 | `instance` |

父窗口发给子页面：

| type | 载荷 |
| --- | --- |
| `identity` | `instance`、`channelId`、可选 `username`、可选 `identityToken`。访客嵌入不带 `identityToken` |

公共字段：`v: 1`，以及 `source` 为 `pavilo-embed` 或 `pavilo-host`。不认识的 `v` 或 `source` 丢掉。

校验：

- `hello` 不含秘密，目标源可以用 `*`。除此之外，子页面发出的消息目标源必须是已经记住的父源，父页面发出的消息目标源必须是 Pavilo 的源。
- 子页面只接受 `event.source === window.parent`，且 `event.origin` 属于配置的祖先。父源从第一条合法 `identity` 记住；其后换源的消息丢掉。
- 父页面只接受 `event.source === iframe.contentWindow`，且 `event.origin` 是 Pavilo。`instance` 必须等于这个 iframe 最近一次 `hello`。换 iframe 或再次 `hello` 就作废旧的 `instance`。
- 凭证只出现在父 → 子的 `identity` 里。子页面不要把凭证放进任何回执。

宿主在每次 `hello` 时重新签发或取出仍有效的 JWT，再回复 `identity`。跳进玩法会换文档，必须再来一轮，不能假设旧页面的内存还在。

过期后的续期就是再发一条 `identity`。嵌入页用新凭证重新 `join`，不增加协议命令。`sub` 变了则先关掉旧连接并丢掉内存里的恢复令牌，避免 v1.4 的 `SESSION_CONFLICT` 把两个人粘在同一席。

## 5. 聊天与玩法切换

宿主模式里，当前频道带 `play` 时，iframe 自己跳到：

```text
/plays/<playId>/?channel=<channelId>&embed=1
```

不带凭证。`client/play.js` 在 `embed=1` 时：

- 不读 `pavilo.resume`，也不因为没有会话就 `location.replace('/')`。
- 同样发 `hello`，等父窗口的 `identity`，再 join。恢复令牌若父窗口没有重新提供，就不要从 `sessionStorage` 捡。
- 切回普通频道、或 echo 的离开，目标是 `/embed?channel=<id>`，不是 `/`。`/embed` 的查询只允许频道 id，不允许凭证。
- 再跳另一个玩法时保持 `embed=1`。

非嵌入的玩法页保持今天的 `pavilo.next` 和回到 `/`。判断条件是查询里的 `embed=1`，不是「只要被嵌住」。这样独立打开玩法页的行为不变。

跳转前，当前页在 `pagehide` 里故意关闭自己的 socket，并取消重连计时器。新文档的 `hello` 成功后再连接。同一席位在服务端应先离开再进入，而不是两条连接同时在线。`pageshow` 且 `persisted` 时再发一次 `hello`，不沿用往返缓存里可能已经过期的连接。

echo 只改离开和启动这两处对嵌入的分支。不把选人器放进 `chat.css` 或 `client/messages.js`。

## 6. 连接生命周期

嵌入页使用现有 `createConnection`。另外约定：

- 内存中的身份对象在故意离开、身份过期、`sub` 变化和文档卸载时清空。
- `pagehide`：`close({ intentional: true })`。不要在卸载过程中再 `scheduleReconnect`。
- 宿主去掉 iframe 后，浏览器关闭 socket；服务端走现有 `removeClient`。验收时看 `/healthz` 的 `clients` 回到嵌入前的数字。租约时间内花名册仍可能留着该席，这是现有 `sessionLeaseMs`，不算连接泄漏。连接数必须下降。
- 宿主换人：新 iframe 是新的 `instance`。旧 iframe 若还在，宿主应先去掉它。示例代码就这样做，不提供「一个容器里叠两个 Pavilo」。

不在本阶段把连接对象暴露给宿主。宿主拆 iframe 就是销毁。

## 7. 示例

新增 `examples/host-embed/`，不要把现在的 `examples/host-identity/` 改成 iframe。那个示例继续证明「宿主自己连 WebSocket」。

新示例：

1. 与身份示例相同的方式登录（可复用同一组 `ada` / `guest` 和 `signHs256`）。
2. 登录成功后在页面里放一个 iframe，`src` 为 `PAVILO_URL + '/embed'`，不附带 token，也不要 `sandbox`。`sandbox` 会挡住脚本和 WebSocket，本阶段不讨论放开哪些 token。
3. 监听 `message`，校验来源和 `instance`，用登录时拿到的 JWT 回复 `identity`。每次 `hello` 都回复，包括玩法页那一次。
4. 页面上能看到未读数和 `identity-expired`。用宿主自己的 DOM 显示，不让 iframe 去改 `document.title`。
5. 提供「离开」：去掉 iframe。再登录另一个用户时必须是新的 iframe。

Pavilo 侧准备：sqlite 示例里用注释写出 `embed.ancestors` 的两项本地源。不把密钥写进示例。README 说明两张名单的差别：这个示例**不**把宿主加进 `allowedOrigins`。

示例不进 Docker 镜像，和 `examples/host-identity/` 一样在宿主机运行。

## 8. 测试与 CI

Node：

- 未配置时 `GET /embed` 为 404；`/`、玩法页、`/admin` 仍是 `X-Frame-Options: DENY`。
- 配置祖先之后，只有 `/embed` 和已启用玩法的页面/资源带 `frame-ancestors`，且没有 `X-Frame-Options`。祖先串里没有 `*`。`/`、`/client/*`、`/admin`、`/room-info` 仍是 `DENY`。
- 非法祖先（通配、带路径、超过 16 个）导致配置校验失败。
- v1 内存配置可以只写 `embed`，不因此要求 `storage`。

浏览器（Playwright，跨来源）：

- 允许的宿主能等到 `ready`，发出一条消息并看到回显。宿主地址栏不变。
- 不在名单里的页面嵌同一 `/embed`，读不到聊天 DOM。
- iframe 的 URL 在登录后仍不含 JWT。
- 进入 echo 再回到普通频道：两次都停在宿主页面内；回到聊天后能再发一条。
- 去掉 iframe 后 `/healthz` 的 `clients` 下降。再次进入使用新用户时，看不到上一个人的内存会话。
- 伪造 `source`、错 `instance`、错来源的 `identity` 不会触发 join。

现有 19 个浏览器用例必须继续通过。它们覆盖的是独立页。

CI：`.github/workflows/ci.yml` 的 `browser-test` 去掉 `continue-on-error: true`。Node 24/26 的 `continue-on-error` 不动。发布说明里写明这次浏览器任务会挡住标签，不要把仍允许失败的 Node 版本说成已经挡住。

## 9. 镜像与发布材料

实现时把启用玩法的 `page/` 和 `assets/` 复制进镜像，延续 HTTP 层「不提供 `host.js` 和 `agents/`」的规则。否则容器里的嵌入只能聊天，玩法一跳就是 404。不要为了示例把 `examples/` 打进镜像。

本文件合入时不改 `package.json`，不打标签。v1.6.0 发布时再更新 README、路线图状态和 CHANGELOG，并把 [集成设计](integration.md) 里已经落地的嵌入字段从「规划」改成「以发布说明为准」。SDK 那一节保持规划。

## 10. 建议实现顺序

1. 配置与响应头，补上 Node 测试。默认部署的现有安全头测试保持绿色。
2. `/embed` 启动路径和消息桥。先只做聊天，玩法频道暂时仍用独立页的跳转，但嵌入模式下先不要跳到会被 `DENY` 的 `/`。
3. `embed=1` 的玩法往返，改 `client/play.js` 和 echo 的离开按钮。
4. `examples/host-embed/` 与浏览器用例。
5. 浏览器 CI 改为阻塞，镜像补上玩法页面资源。
6. 发布 v1.6.0 时再改入口文档。在那之前，README 仍写「没有嵌入 SDK」。

## 已知权衡

- 玩法切换会卸载文档。连接会断一次再 join，不是同一条 socket 换视图。这是为了继续用现有玩法页，而不是在 v1.6 做玩法组件化。
- `frame-ancestors` 对配置里的宿主是公开的。名单不是密钥，但不要把内网主机名写成比部署所需要更宽的源。
- 宿主若自己把 iframe 指到 `/plays/<id>/?embed=1`，消息桥同样能工作。对外只承诺先打开 `/embed`。
- 嵌入页不改标题、不弹系统通知。宿主没听 `unread` 时，用户就只有 iframe 里的未读提示。
- 关闭第三方 Cookie 之后，独立页那种刷新恢复不在嵌入路径上提供。宿主要在每次 `hello` 时把人再送进来。
