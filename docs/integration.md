## 交付形态与接入流程

首批服务个人开发者和小型社区。一个独立 Pavilo 实例优先服务一个宿主应用；宿主可以用任意后端语言，不要求和 Pavilo 同进程或同源部署。

目标接入流程：

1. 部署 Pavilo，选择预设和存储模式，在配置或后台预建频道。
2. 配置允许嵌入的宿主来源与身份信任关系；两者不是同一权限。
3. 宿主后端依据现有登录态签发短期接入凭证，声明稳定用户和允许访问的频道。
4. 宿主页面加载 SDK，提供容器、服务地址、目标频道、外观和获取凭证回调。
5. SDK 挂载嵌入页，完成凭证传递、能力读取与聊天；宿主按需订阅未读和连接等事件。
6. 宿主退出或切换用户时通知 SDK，清理旧用户的连接、凭证与页面状态；续期失败时显示重新认证状态，不降级成有权限的访客。

匿名接入可省略宿主凭证，但仍受服务器允许访客的设置及频道策略限制。

## 功能组装边界

| 层次 | 配置职责 | 约束 |
| --- | --- | --- |
| 实例 | 存储、身份接入、网关、已安装模块、宿主来源 | 存储模式不由嵌入页面选择；服务端密钥不公开 |
| 频道 | 图片、回复、回应、提及、输入提示、历史访问、访问权限、审核、玩法绑定 | 只能使用实例已提供且依赖满足的能力 |
| 用户 | 经验证的身份与频道权限 | 用户授权不能打开实例或频道关闭的能力 |
| 嵌入界面 | 颜色、明暗主题、语言、标题、品牌展示、面板显隐 | 隐藏 UI 不等于禁止操作，界面不能扩大服务端权限 |

服务端计算有效能力并向获授权客户端提供必要信息；客户端只展示实际可用功能。配置缺少依赖在启动或保存时明确失败，运行期外部服务不可用走相应失败策略，不伪装成功。

目标预设为临时聊天室、持久社区、嵌入聊天、聊天＋玩法。身份验证不强制 SQLite；当前 Play 对 SQLite 的依赖保留，Agent 模型调用需要可用网关。不开启某项功能不意味着自动移除其它模块依赖。

现有 YAML 和管理后台覆盖层继续按 [配置文档](configuration.md) 工作。后续新增字段由实现 ADR 定义，并明确是否可由后台编辑及实际配置来源；不引入第三套由浏览器控制的配置真源。

## 身份与授权数据流

```text
宿主登录态 → 宿主后端签发短期凭证 → SDK → Pavilo 身份验证
                                               ↓
                                     稳定用户 + 会话 + 频道授权
                                               ↓
                            频道发现 / 历史 / 发言 / Play 动作
```

- 稳定用户、临时会话、网络连接和 Agent 席位分别建模。昵称是显示信息，不能作为防冒充、历史归属或长期封禁的主键。
- 验证签名、签发者、受众和有效期；明确算法白名单，不按不可信令牌自由选择算法。依据 [RFC 8725](https://www.rfc-editor.org/rfc/rfc8725.html)。具体凭证字段与密钥轮换配置在功能实现时通过 ADR 固定，当前不构成可调用契约。
- 续期、退出、身份切换和过期是 SDK 生命周期的一部分。凭证和旧身份状态不能在组件重新挂载时串用。
- 授权覆盖频道发现、加入、历史读取、发送、回应等受控操作与玩法动作，不能只在首次登录时检查。
- 临时恢复 token 不等于宿主身份；恢复连接仍需满足当前身份及权限要求。Agent 的私密状态不能仅凭客户端传入 actor ID 获取。
- operator 管理凭证与用户接入凭证分离；前端不持有签名密钥、operator token 或模型 API key。
- v2.0 只接入预建频道。后端动态建频道、租户目录、注册/密码/找回不在范围内。

## SDK 与嵌入页面

下表是目标能力清单，方法名、URL 和事件载荷待对应实现 ADR 固定，不能据此调用当前服务。

| 接口面 | 必须提供的行为 |
| --- | --- |
| 初始化与挂载 | 指定容器、服务地址、预建频道、获取凭证回调和外观配置；失败可诊断 |
| 生命周期 | 就绪、销毁；销毁释放连接、监听器与身份状态，允许宿主重新挂载 |
| 身份 | 获取/续期短期凭证；响应退出、身份切换、过期与重新认证 |
| 频道 | 在授权频道间切换；聊天与玩法切换留在嵌入区域 |
| 外观 | 更新颜色、明暗主题、语言、标题、品牌展示和面板显隐 |
| 事件 | 就绪、连接状态、未读、身份过期和结构化错误；不泄露凭证和其它用户私密状态 |

SDK 包裹独立 iframe 页面，复用聊天协议、状态、pending、重连和 Play 宿主，不复制另一套聊天实现。身份通过受校验的消息桥传递，不写 URL，也不依赖第三方 Cookie。浏览器存储不可用时仍应完成认证和聊天，可由宿主重新提供凭证。

只对指定嵌入入口开放配置过的宿主来源；独立页和后台保持原有防嵌入边界。需要同时处理嵌入响应的 X-Frame-Options 与 CSP，不能全站撤销保护。使用 [CSP frame-ancestors](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP) 控制嵌入方；[postMessage](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage) 使用精确目标来源，并校验接收消息的来源、发送窗口、实例关联和载荷。

宿主页面的标题、系统通知和滚动由宿主管理；嵌入页通过事件提出信息，不复用独立页会修改整个页面的副作用。外观只提供品牌与布局配置，不开放任意 HTML、脚本或内部组件替换。

SDK 交付可自托管浏览器脚本、npm 分发和类型声明；提供原生 JavaScript、React、Vue 最小示例。核心前端不因此引入框架依赖。当前仓库 `private: true`，本次不修改包发布设置；SDK 包边界与发布流程在 SDK 阶段建设。

## 治理与故障处理

- 官方基础闭环：访问控制、限流、禁言/封禁、举报、管理员移除内容和操作记录，不做审核工单或申诉系统。
- 持久社区的治理记录落 SQLite；临时模式状态随进程结束。内容移除使用可同步标记，历史分页、回复引用和已连接客户端不能继续展示已移除正文。
- 审核在提交前完成，外部审核不阻塞事件循环。审核结束后复查身份、权限、频道状态和幂等性，再提交消息；SQLite 提交后才 ACK。
- 配置严格审核时依赖故障、超时均拒绝提交；临时场景可显式选择放行。拒绝或未完成审核不能发成功 ACK。
- 提交后事件有队列边界、超时和错误记录；失败不回滚已经接受的消息，不承诺可靠消息总线或恰好一次外部投递。
- 人和 Agent 的公开消息都走统一权限、限额和审核路径。Play 私密状态继续限制接收者，切频道或更换身份后不得沿用旧视图。
- Play/Agent 可捕获异常按模块故障处理；可信脚本的无限循环、进程退出或任意系统访问不属于沙箱隔离保障。
- 公网配置需覆盖 TLS、可信代理、身份/访问控制、资源限制和留存策略；可信代理和滥用防护随治理主线完善。嵌入能力不等于可以裸露端口。

## 验收与兼容

用两个可运行示例验收：一个已有登录的普通产品接入预建频道；一个小型社区按需启用持久化、治理和狼人杀。示例要能从干净环境按文档复现，不通过修改内核完成集成。

必须测试跨来源嵌入、非法来源/窗口消息、凭证伪造与过期、退出/身份切换、第三方 Cookie 禁用、频道与历史越权、禁用能力绕过、重复挂载销毁、聊天/玩法切换和隐私边界。浏览器与支持的 Node 版本检查在 v2.0 成为发布门槛。

v1.x 的现有协议与配置承诺继续有效。预览 SDK 标注实验状态；v2.0 冻结稳定接入和扩展契约，并记录版本兼容表、弃用路径及迁移步骤。具体线协议、字段和新版本号不在产品规划中预先杜撰。

暂缓无界面 SDK、深度组件替换、Node 后端库嵌入、动态建频道、多租户和市场。WebView 只作探索；原生 SDK 与系统推送不作为 v2.0 门槛。
